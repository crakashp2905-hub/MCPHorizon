## N29 — K2: confined runner and sink anchor (CANDIDATE)
`horizon/runtime/runner.py` runs an agent under the enforced sandbox policy by default and REFUSES weaker policies (`POLICY_TOO_WEAK`); the agent edits a private workspace copy and changes are only reported. 14 bypass probes (tcp/udp/raw/unix sockets, writes/reads outside the workspace, symlink/hardlink escape, exec variants, mount, setuid) are all blocked confined and reachable unconfined (control). `FileSink` now records (count, head) after every append, so tail truncation is detected without a caller-supplied anchor.
Limits, stated plainly: proven only on THIS kernel as root in a cloud container — NOT on the owner's designated Linux host (BLOCKED until they supply it); the runner is not yet the mandatory start path for every agent; the anchor sits beside the journal by default so an attacker who rewrites both (or restores both) is not detected (test documents it); ProcessIssuer failure stays fail-closed with no auto-restart because a respawned issuer would mint a different key; no mutation testing was run on K2; running the unconfined control `mount` probe as real root would shadow the host /proc, so it is skipped when unconfined (this crashed the sandbox twice before the fix). Nothing here is independently verified.
